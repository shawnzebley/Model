# Compliance check

Run this before drafting. Every item, every time. Fire protection content carries
liability that ordinary marketing content does not.

## 1. Customer identification

Default to anonymized. "A 200-unit high-rise in Wilmington" is publishable.
"Riverside Towers" is not, unless Shawn confirms permission.

Anonymize by: building type, approximate size, general geography, occupancy class.
Never: name, address, cross streets, distinctive architecture in a photo, a unit
count so specific it identifies the property in a small market.

Ask Shawn directly: "Can I name this one?" Do not assume, and do not infer
permission from the fact that he sent you the report.

## 2. Open deficiencies

If the deficiency is still open, it does not go out as public content. A post
about an uncorrected life safety violation at an identifiable property is a
problem for the customer and for Sobieski.

Closed and corrected is fine, and is usually the better story anyway because it
has an ending.

## 3. Code interpretation

Shawn can state what NFPA 10, 25, or 72 requires. He cannot state how a specific
AHJ will rule. Those are different claims.

Write: "NFPA 25 requires quarterly inspection of these valves."
Do not write: "This will pass inspection" or "Your AHJ will accept this."

When a post explains a requirement, cite the standard and edition where possible.
Where local amendments commonly differ, say so.

## 4. Competitors

Never identify the company that did deficient prior work, and never imply it.
"The previous contractor" is already too close in a small market. Use "it had
been signed off in a prior year" or describe the condition without an actor.

## 5. Photos

- No property-identifying features (signage, address, distinctive exterior)
- No open deficiency at an identifiable property
- Nothing containing a panel display with a site name
- No people without their consent
- Check the background. Reflections and adjacent signage give away location.

## 6. Numbers

Every figure traces to something real. Deficiency counts, dollar amounts, dates,
device counts. If Shawn has not given you the number, do not produce one, and do
not round a real number up for effect.

If a cost-of-failure figure is an estimate, label it an estimate and say what it
is based on.

## Fast version

Anonymized? Deficiency closed? Code claim limited to the standard, not the ruling?
Competitor unidentifiable? Photo clean? Every number real?

Any no, fix it or drop the post.
